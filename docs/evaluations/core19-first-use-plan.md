# Synthetic blank first-use acceptance plan

Status: prospective scope for the trusted nine-file prepared transition. This
plan uses only synthetic identities/content, local Git remotes and native
consumer samples. It does not authorize real installation, deployment or merge.

## Frozen behavior question

Can a genuinely blank, supplied Instance reach a usable current learning unit
through a trusted inactive-first transition; recover its own exact accepted
candidate after lost response; save one genuine synthetic interaction position;
and give a fresh read-only consumer enough canonical context to select a sensible
next action without the producer transcript or a writable-generation claim?

The fixed teaching route is next-token prediction and tokens/context. Core's
existing `modern-language-models` curriculum supplies the nodes. Unknown learner
background/deadline/preferences remain unknown. No Knowledge or Evidence is
created merely to make this evaluation pass.

## Structural acceptance

N: blank Git tree, complete prepublication nine-file graph, exactly one
changed path per accepted commit, all inactive prefixes denied by ordinary open,
unique generation 1, ten accepted transitions, useful checkpoint and cold
read-only recovery. Only checkpoint-authorized fields may change.

L1: every create/activation acceptance point loses its transport response before
the publisher completion marker or receipt confirmation. A restarted adapter
uses only durable receipt/prepared objects and current authority to inspect and
continue. L2: prepared/unpublished effect is retried with exactly the same commit.
L3: target-slot race and same-op concurrency; equal bytes from another commit are
not our effect. L4: external and preparation-bug mode-only changes rejected from
Git tree identities, regardless of chmod support. L5: missing/corrupt evidence,
unreadable outcome, unfamiliar successor or undrained publisher stop later writes.

R: missing/revoked grant, stale/frozen deployment, invalid inputs, unsupported
provider, cleanup failure and unknown prior writer all fail closed. Revocation
after accepted activation reports that activation without rollback or capability.

## Consumer sample and rubric (freeze before dispatch)

One independent-context producer A receives only safe initial Goal, Topic Plan,
current Subtopic Plan and Progress, this synthetic learner request, and a minimal
role: “Explain next-token prediction with a short example, then introduce how
tokens/context affect it. Do not infer my mastery or invent prior knowledge.”
A must offer a useful explanation and a concrete example. Then the fixed
synthetic learner response is: “For ‘the cat sat on the’, ‘mat’ could be likely.
A token may be part of a word. I still want to compare what ‘bank’ means beside a
river and in a money-related sentence.” No diagnostic Knowledge claim follows.
A's actual teaching action and this response justify only a saved position and
ready-next item. They do not demonstrate genuine human learning.

A passes if it correctly describes conditional next-token prediction, distinguishes
tokens from necessarily whole words, uses a meaningful example, acknowledges
that likely continuation is not factual truth, and proposes a manageable next
step. Any false mastery claim fails the sample regardless of structural success.

Consumer B is a different independent context, after A is closed. Its packet is
produced by a new-process read-only Host: current Goal/Plan/Progress and bound-unit
discovery only. It receives no A transcript, token, returned Evidence ID or raw
receipt. Acceptable next-action classes are (a) compare river-bank versus
money-bank contexts; (b) briefly clarify token segmentation, then do that context
comparison. It must cite the saved position/ready-next as the reason, avoid
mandatory repeated intake, and distinguish unknown mastery from inability.
B is not asked to produce or obtain a writable generation. An attempted write
through its read-only Host must be denied without a canonical mutation.

Keep actual packets/responses and their hashes at the evaluation owner; do not
rewrite them to fit the rubric. One A/B pair is one synthetic behavior sample.
Mechanical replay is not a new independent sample. Structural tests, sampled
consumer behavior, long-term reliability and real learning benefit remain
separate claims. Linux and Windows actual runs must be reported separately.
